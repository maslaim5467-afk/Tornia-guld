# نمای کلی پروژه — Tornia-guld

> وضعیت: سند پایه / پیش‌نویس  
> هدف: ثبت تصمیم‌های تأییدشده و جدا نگه‌داشتن آن‌ها از ایده‌هایی که هنوز در حال بررسی‌اند.

## ۱. معرفی کوتاه

Tornia-guld نام فعلی پروژه‌ی یک بازی با سبک بصری دوبعدی Pixel Art است. موتور اختصاصی پروژه علاوه بر مسیر دوبعدی، اکنون دارای زیرساخت آزمایشی رندر سه‌بعدی نیز هست؛ پشتیبانی موتور از 3D به معنی تغییر سبک بصری بازی اولیه نیست. فضای موردنظر، جهانی تخیلی و فانتزی است که در آن جادو و مهارت‌های گوناگون وجود دارند.

نام پروژه در این مرحله نام کاری محسوب می‌شود و نهایی بودن آن تأیید نشده است.

## ۲. تصمیم‌های تأییدشده

- **سبک بصری بازی اولیه:** دوبعدی (2D) با Pixel Art.
- **قابلیت گرافیکی موتور:** زیرساخت‌های رندر دوبعدی و سه‌بعدی (2D/3D) در یک پروژه؛ وضعیت آن‌ها در اسناد فنی تفکیک شده است.
- **جهت هنری:** Pixel Art.
- **فضای جهان:** فانتزی و تخیلی.
- **عناصر جهان:** وجود جادو و مهارت‌های مختلف.
- **رویکرد توسعه:** ابتدا ایده‌ها، جهان، داستان و طراحی سیستم‌ها مستند شوند؛ سپس بر اساس تصمیم‌های تثبیت‌شده وارد پیاده‌سازی شویم.
- **مالکیت خلاقانه:** تصمیم‌های نهایی داستان و طراحی بازی با خالق پروژه است. این سند نباید ایده‌های پیشنهادی را بدون تأیید او به تصمیم قطعی تبدیل کند.

## ۳. پلتفرم و فناوری توسعه

تصمیم‌های تأییدشده برای نسخه‌ی نخست:

- **پلتفرم هدف نسخه‌ی اول:** Android.
- **زبان برنامه‌نویسی:** C.
- **رندرینگ گرافیکی:** Vulkan.
- **رویکرد موتور:** توسعه‌ی موتور اختصاصی پروژه؛ استفاده از موتورهای آماده مانند Godot تأیید نشده و در محدوده‌ی فعلی نیست.
- **چرخه‌ی اجرای Android در Prototype:** Android NativeActivity با Android Native App Glue.
- **معماری ساخت اولیه:** الگوی فنی زنجیره‌ی ساخت OLREDINE، با سورس و خروجی مستقل برای Tornia-guld.
- **کامپایل Native:** Android NDK و Clang برای ABI اولیه‌ی `arm64-v8a`.
- **ساخت APK:** اسکریپت `build.sh` برای کامپایل Shaderها، کد C، بسته‌بندی، هم‌ترازسازی و امضای APK.
- **ساخت خودکار:** GitHub Actions با اجرای خودکار روی Push به `main` و اجرای دستی از طریق `workflow_dispatch`.

تنظیمات اولیه‌ی Prototype عبارت‌اند از حداقل Android API 24، هدف Android API 34، Android NDK نسخه‌ی 26.1.10909125، Build Tools نسخه‌ی 34.0.0 و Vulkan 1.0. این‌ها تنظیمات شروع هستند و پیش از انتشار یا افزایش دامنه‌ی پشتیبانی باید روی دستگاه‌های هدف ارزیابی شوند.

نکته‌ی فنی: Vulkan یک API گرافیکی است، نه موتور کامل بازی. پروژه اکنون دارای زیرساخت‌های اولیه‌ی اجرای Android، ورودی، جهان و بازیکن دوبعدی، انیمیشن، محاسبات و دوربین سه‌بعدی، Mesh و منابع GPU، صحنه‌ی آزمایشی دریا، آسمان و وضعیت آب‌وهوا است. بااین‌حال، معماری مستقل و کامل Rendererها، هماهنگ‌کننده‌ی عمومی صحنه‌ها، برخورد و فیزیک کامل، مدیریت NPC، ذخیره‌سازی، صدا و خط لوله‌ی جامع دارایی‌ها هنوز تکمیل نشده‌اند. جزئیات در `TECHNICAL_DESIGN.md` و `ENGINE_IMPLEMENTATION_STATUS.md` ثبت می‌شود.

## ۶. مواردی که هنوز تعیین نشده‌اند

موارد زیر عمداً باز هستند و برای آن‌ها تصمیم قطعی ثبت نشده است:

- ژانر دقیق و زیرژانر بازی.
- نسخه‌ی حداقل Android و فهرست دستگاه‌های هدف.
- حداقل نسخه و قابلیت‌های موردنیاز Vulkan روی دستگاه‌های هدف.
- محیط و زنجیره‌ی ساخت (Toolchain)، از جمله Android NDK و روش ساخت APK.
- ساختار گیم‌پلی و چرخه‌ی اصلی بازی (Core Gameplay Loop).
- شیوه‌ی مبارزه و تعامل با محیط.
- ساختار جهان: خطی، نیمه‌باز یا جهان‌باز.
- دوربین و زاویه‌ی نمایش.
- قوانین جادو، محدودیت‌ها و روش یادگیری مهارت‌ها.
- سیستم پیشرفت شخصیت و رشد توانایی‌ها.
- مدت و ساختار روایت و میزان آزادی بازیکن.
- زبان‌های بازی.
- معماری دقیق موتور اختصاصی و زیرسیستم‌های آن.
- قالب و خط لوله‌ی واردکردن Spriteها و سایر دارایی‌ها.
- سیستم صدا، ذخیره‌سازی و مدیریت منابع.
- مدل انتشار و درآمدزایی.

## ۷. اصل مدیریت تصمیم‌ها

برای جلوگیری از تناقض در مستندات:

1. تصمیم تأییدشده از ایده‌ی پیشنهادی جدا نوشته شود.
2. هر مورد نامشخص با برچسب «نیازمند تصمیم» باقی بماند.
3. هیچ قابلیت یا ویژگی صرفاً به دلیل پیشنهاد دستیار، وارد محدوده‌ی قطعی بازی نشود.
4. پس از تغییر یک تصمیم مهم، اسناد وابسته نیز بازبینی شوند.

## ۸. گام بعدی

گام فنی بعدی، تثبیت ادغام زیرساخت‌های دوبعدی و سه‌بعدی در شاخه‌ی اصلی، همگام‌سازی مستندات، اجرای CI روی ترکیب نهایی و سپس اعتبارسنجی نصب و عملکرد روی دستگاه‌های Android هدف است. توسعه‌ی قابلیت‌های جدید گرافیکی تا زمان ارزیابی عملکرد و تثبیت معماری در اولویت نیست.
